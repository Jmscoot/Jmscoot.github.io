# 라이브러리(Library)

컴파일/링킹/실행 단계별 추가되는 라이브러리 파일들이 다르다.

## 단계별 라이브러리 파일

| 단계 | 종류 | 추가되는 시점 | 대상파일 |
|------|------|-------------|---------|
| 컴파일 | 헤더 | 컴파일 직전에 텍스트 구문(선언) 복붙 | .h |
| 링킹 | 정적 라이브러리 | 링킹 때 코드 복붙 | .a .dll.a .lib |
| 실행 | 동적 라이브러리 | 링킹 때 비카을 맺고, 실행 때 채운다. | .dll |

## 예시: GLFW 3.4.0

예를 들어 GLFW 3.4.0이라는 소스코드를 빌드하면 glfw3.h, libglfw3.dll.a, glfw3.dll 라이브러리 파일들이 생성된다. 여기서 glfw3.h는 컴파일 단계에서 추가가 되고, libglfw3.dll.a는 링킹단계에서, glfw3.dll은 실행단계에서 추가가 된다.

### 32bit vs 64bit 라이브러리

라이브러리가 32bit짜리가 있고 64bit짜리가 있는데 섞어서 빌드가 안된다.

| 목록 | 32bit | 64bit |
|------|-------|-------|
| DAQ grabber lib | USB3-FRM13.dll | USB3-FRM13_x64.dll |
| GLFW 런타임 | glfw3.dll | glfw3.dll |
| GLFW import lib | libglfw3dll.a | |
| GLEW | glew32.dll, glew32.lib | |
| pthread | libwinpthread-1.dll | libwinpthread-1.dll |

## 정적 vs 동적 라이브러리

**정적 라이브러리**: 컴파일할 때 라이브러리 코드가 실행파일에 직접 포함된다. 각 프로그램이 복사본을 보유하고 있다. 그래서 파일 크기가 크는 단점이 있다. 반면에 동적 라이브러리는 컴파일할때만 찾으므로 메모리 절약이 가능하다는 장점이 있다.
